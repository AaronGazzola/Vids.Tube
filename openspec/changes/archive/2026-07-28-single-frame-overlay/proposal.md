# Single-frame overlay: one OBS URL, token auth, live Preview-tab editing

## Why

The overlay system today is six separate OBS browser sources (highlights,
3 goal bars, competition, break), each hand-positioned in OBS; the saved
layout's `x`/`y` never reach OBS (only per-box scale does), positioning truth
is split between the demo stage and OBS, and layout can only be edited in
demo mode with fake data. Linear AZ-175 + AZ-176; `docs/roadmap.md` V2.

## What Changes

- `demo_layouts` renames to `overlay_layouts` and gains a `token` column
  (generated by default). The config gains `competitionOpacity` and
  `feedSound` fields; old configs merge forward with defaults.
- `/overlay/[channelSlug]` becomes THE single overlay frame: a fixed
  1080×1920 transparent canvas rendering every enabled element absolutely
  positioned from the saved config (feed slot, 3 goal bars, competition
  ladder, break card). It requires `?token=` to match the channel's token.
- The per-element routes (`/goals`, `/goals/[metric]`, `/competition`,
  `/break`) are deleted immediately — no transition period. Their hooks and
  actions remain (consumed by the frame and the live dashboard).
- Layout changes push over a realtime broadcast channel
  (`overlay-layout:{slug}`) so OBS reflects edits within ~1s; the 15s poll
  remains as fallback.
- The /live Preview tab gains a live overlay editor (no demo mode needed):
  draggable/resizable outline boxes over the real HLS preview, element
  visibility switches, competition opacity, feed sound (chime/off), reset,
  and copy-URL. Saves via the existing debounced layout persistence, which
  now runs whenever /live is open.
- Settings → "OBS overlays" collapses to one URL row (with token) + a
  regenerate-token button. Dimension hints and the opacity slider disappear.
- The demo stage keeps working unchanged as the demo-mode surface (same
  store, same table).

## Capabilities

### Modified Capabilities

- `stream-overlays`: single full-canvas overlay route with token auth and
  realtime layout push replaces the six per-element routes; layout/styling
  is editable live from the Preview tab.

## Impact

- Migration renames `demo_layouts` → `overlay_layouts` (adds `token`). The
  currently deployed production build reads `demo_layouts` until this change
  deploys — overlays/demo layout are briefly inconsistent in prod between
  `db push` and the code deploy. Acceptable: no stream is live during the
  window.
- The owner's OBS scene must be rebuilt once: remove the six browser
  sources, add one at 1080×1920 (full canvas) with the new tokened URL.
